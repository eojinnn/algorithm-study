# Greedy Algorithm (그리디 알고리즘)

> **핵심:** 현재 상황에서 가장 유리하다고 판단되는 선택을 반복하여 답을 구하는 알고리즘 설계 기법.
>
> **주의:** 매 순간 최선의 선택을 한다고 해서 항상 전체 최적해가 나오는 것은 아니다. 해당 문제에서 **그리디 선택이 정당한 이유**를 확인해야 한다.

## 1. 개념

**그리디(Greedy)** 알고리즘은 전체 경우의 수를 모두 탐색하는 대신, 매 단계에서 정해진 기준에 따라 **국소적으로 최적인 선택**을 수행한다.

- **국소 최적(local optimum):** 현재 단계에서 가장 좋다고 판단되는 선택
- **전역 최적(global optimum):** 문제 전체에서 가장 좋은 결과
- **그리디의 목표:** 국소 최적 선택을 반복해 전역 최적해를 얻기

일반적인 접근 흐름은 다음과 같다.

```text
문제의 목표 확인
     ↓
현재 단계의 선택 기준 수립
     ↓
정렬 / 우선순위 큐 등으로 후보 관리
     ↓
유효한 선택인지 확인
     ↓
선택하고 상태 갱신
     ↓
모든 후보를 처리한 뒤 결과 반환
```

그리디는 **특정 자료구조가 아니라 전략**이다. 반드시 정렬해야 하는 것도 아니며, 문제에 따라 정렬, 힙, 투 포인터 등을 조합한다.

## 2. 언제 그리디를 의심할까?

문제에 다음과 같은 특징이 있다면 그리디를 고려해 볼 수 있다.

- 최소 개수, 최대 이익, 가장 빠른 완료 등 **최적화 목표**가 있다.
- 후보를 **일정한 기준으로 정렬**할 수 있다.
- 현재 선택이 이후의 선택 가능 범위를 좁히거나 바꾼다.
- 한 번 선택한 결과를 **되돌리지 않고** 진행하는 전략을 생각할 수 있다.

단, 이는 **힌트일 뿐 충분조건이 아니다.** 이런 특징이 있어도 DP, 완전탐색, 이분탐색 등이 정답일 수 있다.

## 3. 문제를 풀 때 스스로 물어볼 질문 (Greedy Checklist)

1. **목표가 무엇인가?** 최소화할 값 또는 최대화할 값은?
2. **현재 단계에서 무엇을 선택할 수 있는가?** 선택 가능한 후보와 제약 조건은?
3. **무슨 기준으로 고르면 좋은가?** 작은 값부터, 큰 값부터, 종료 시점이 빠른 것부터 등
4. **그 선택이 미래의 더 좋은 해를 막지는 않는가?** 반례를 만들 수 있는가?
5. **선택 기준을 어떻게 빠르게 구현할까?** `sort`, `sorted`, `heapq`, 투 포인터 등
6. **시간복잡도는 얼마인가?** 특히 정렬과 힙 연산 비용을 포함했는가?

### 그리디가 맞는지 확인하는 대표적인 논증

**교환 논증(Exchange Argument):** 최적해에 내 선택이 들어 있지 않더라도, 최적해의 일부를 내 선택으로 교체했을 때 결과가 나빠지지 않음을 보인다. 그러면 적어도 하나의 최적해가 내 선택을 포함한다.

**반복 적용:** 첫 번째 선택 이후 남은 부분 문제에도 같은 논리를 적용할 수 있으면 그리디 전략이 정당화된다.

**반례 검사:** 작은 입력을 직접 나열하거나 완전탐색 결과와 비교하여 전략이 틀리는 경우를 찾아본다.

## 4. 대표적인 구현 패턴

### 패턴 A. 정렬 → 조건 검사 → 선택

```python
# 문제에 맞는 정렬 기준과 선택 조건을 정의해야 한다.
items = sorted(items, key=lambda x: x[1])
answer = 0
state = initial_state

for item in items:
    if can_select(item, state):
        state = apply_selection(item, state)
        answer += 1
```

- `can_select`, `apply_selection`, `initial_state`는 **설명용 자리표시자**이며 Python 내장 함수가 아니다.
- 이 뼈대만으로 정답이 보장되지 않는다. **정렬 기준과 선택 규칙**을 증명하거나 반례로 검증해야 한다.

### 패턴 B. 우선순위 큐(Heap)

```python
import heapq

heap = [4, 1, 7, 2]
heapq.heapify(heap)           # 최소 힙 생성: O(N)

while heap:
    smallest = heapq.heappop(heap)  # 최솟값 제거: O(log N)
    print(smallest)
```

최댓값부터 꺼내려면 숫자에 음수를 붙여 최소 힙으로 다룰 수 있다.

```python
import heapq

heap = []
for x in [4, 1, 7, 2]:
    heapq.heappush(heap, -x)

largest = -heapq.heappop(heap)  # 7
```

### 패턴 C. 정렬 + 투 포인터

```python
arr.sort()
left, right = 0, len(arr) - 1

while left < right:
    # 문제에서 정의한 조건에 따라
    # left와 right 중 어느 쪽을 이동할지 결정
    if should_move_left(arr, left, right):
        left += 1
    else:
        right -= 1
```

- `should_move_left`는 **설명용 자리표시자**다.
- 투 포인터는 그리디와 자주 함께 쓰이지만, 모든 투 포인터 풀이가 그리디인 것은 아니다.
- 각 포인터를 되돌리지 않고 움직인다면 정렬 이후 순회는 보통 **O(N)**이다.

## 5. Python 핵심 함수와 문법

| 함수 / 문법 | 역할 | 대표 시간복잡도 |
|---|---|---|
| `arr.sort()` | 리스트 원본 오름차순 정렬 | O(N log N) 최악 |
| `arr.sort(reverse=True)` | 원본 내림차순 정렬 | O(N log N) 최악 |
| `sorted(iterable)` | 정렬된 **새 리스트** 반환 | O(N log N) 최악 |
| `key=lambda x: x[1]` | 두 번째 값을 기준으로 정렬 | 정렬 O(N log N), 키 계산 별도 |
| `key=lambda x: (x[0], -x[1])` | 첫 값 오름차순, 두 번째 숫자 내림차순 | 정렬 O(N log N), 키 계산 별도 |
| `min()`, `max()` | 값 중 최솟값/최댓값 선택 | N개 대상 O(N) |
| `heapq.heapify(arr)` | 리스트를 최소 힙으로 변환 | O(N) |
| `heapq.heappush(heap, x)` | 힙에 삽입 | O(log N) |
| `heapq.heappop(heap)` | 힙의 최솟값 제거 및 반환 | O(log N) |
| `heap[0]` | 최소 힙의 최솟값 조회 | O(1) |
| `enumerate(arr)` | 인덱스와 값을 함께 순회 | 전체 순회 O(N) |

> `sort()`는 원본을 수정하고 `None`을 반환한다. `sorted()`는 새 **list**를 만든다. `deque`에는 `.sort()`가 없다.

### 다중 조건 정렬

```python
items = [(2, 4), (1, 9), (2, 7), (1, 3)]

# 첫 값 오름차순, 같으면 두 번째 값 내림차순
items.sort(key=lambda x: (x[0], -x[1]))
print(items)
# [(1, 9), (1, 3), (2, 7), (2, 4)]
```

`reverse=True`는 모든 정렬 기준의 순서를 뒤집는다. 일부 기준만 반대로 정렬하려면 숫자 키에 `-`를 붙이는 방식을 고려한다.

## 6. 그리디가 항상 맞지는 않는 예

**동전 종류가 `[1, 3, 4]`, 만들어야 할 금액이 `6`**이라고 하자.

- 가장 큰 동전부터 선택하는 그리디: `4 + 1 + 1` → **3개**
- 실제 최적해: `3 + 3` → **2개**

즉, **가장 큰 값을 우선 선택한다**는 그리디 전략은 이 문제에서 실패한다. 선택 기준이 그럴듯해 보여도 정답을 보장하는지 확인해야 한다.

## 7. 그리디와 다른 알고리즘 비교

| 방법 | 핵심 사고 | 적합한 상황 |
|---|---|---|
| 그리디 | 지금 가장 유리한 선택을 확정 | 국소 선택의 최적성이 보장될 때 |
| DP | 부분 문제의 결과를 저장하고 조합 | 중복 부분 문제와 점화식이 있을 때 |
| 완전탐색 | 가능한 선택을 모두 확인 | 경우의 수가 작거나 검증용 정답이 필요할 때 |
| 이분탐색 | 가능/불가능의 경계를 좁힘 | 판정 결과가 단조성을 가질 때 |

**중요:** 최적화 문제라는 이유만으로 그리디를 선택하지 않는다. 먼저 그리디가 항상 최적해를 만든다는 근거가 있어야 한다.

## 8. 시간복잡도 체크

- **정렬 + 1회 순회:** 일반적으로 O(N log N)
- **이미 정렬된 입력 + 1회 순회:** 일반적으로 O(N)
- **N회 힙 삽입/삭제:** 일반적으로 O(N log N)
- **투 포인터 순회:** 포인터가 각자 한 방향으로만 이동하면 O(N) (정렬 비용 별도)
- **공간복잡도:** 원본 수정 여부, 별도 배열, 힙 사용 여부를 모두 확인한다.

