# Dynamic Programming (DP)

> **핵심 아이디어:** 같은 작은 문제를 여러 번 계산하지 않고, **한 번 구한 결과를 저장해서 재사용**하는 문제 해결 기법.

Python에는 `dp()`라는 전용 함수가 없다. 보통 **리스트(`list`)**, **딕셔너리(`dict`)**, 또는 **`functools.cache`**로 구현한다.

## 1. DP란 무엇인가?

Dynamic Programming(동적 계획법)은 **큰 문제를 작은 문제로 나누고**, 작은 문제의 답을 저장해 큰 문제의 답을 구하는 방식이다.

DP를 고려할 만한 문제에는 주로 다음 특징이 있다.

- **중복되는 부분 문제(Overlapping Subproblems):** 같은 작은 문제를 반복해서 계산한다.
- **부분 문제로부터 답을 만들 수 있음(Optimal Substructure):** 작은 문제의 정답을 조합해 큰 문제의 정답을 구할 수 있다. (최댓값·최솟값뿐 아니라 경우의 수 문제에도 활용할 수 있다.)

### DFS 완전탐색과 DP의 차이

```text
단순 재귀/DFS: 가능한 경로를 따라가며 같은 상태를 여러 번 계산할 수 있음
DP:          상태별 답을 저장하여 같은 상태는 다시 계산하지 않음
```

**주의:** 모든 DFS를 DP로 바꿀 수 있는 것은 아니다. 서로 다른 경로라도 **앞으로의 결과가 동일한 상태로 표현될 때** 중복 계산을 줄일 수 있다.

## 2. 문제를 풀 때 생각할 4가지

| 순서 | 질문 | 예시 |
|---|---|---|
| 1. 상태 정의 | `dp[i]`가 정확히 무엇을 의미하지? | `i`번째 위치에 도착하는 방법의 수 |
| 2. 점화식 | 더 작은 상태로 현재 답을 어떻게 계산하지? | `dp[i] = dp[i-1] + dp[i-2]` |
| 3. 초기값 | 가장 작은 입력의 정답은? | `dp[1] = 1`, `dp[2] = 2` |
| 4. 계산 순서·정답 | 어떤 순서로 채우고 무엇을 반환하지? | 작은 `i`부터 계산한 후 `dp[n]` 반환 |

이 중 **가장 중요한 것은 상태 정의**다. 상태가 모호하면 점화식을 올바르게 만들기 어렵다.

## 3. 예제로 이해하기: 피보나치

피보나치 수열은 다음과 같다.

```text
F(0) = 0
F(1) = 1
F(2) = F(1) + F(0) = 1
F(3) = F(2) + F(1) = 2
F(4) = F(3) + F(2) = 3
F(5) = F(4) + F(3) = 5
```

점화식:

```text
F(n) = F(n-1) + F(n-2)   (n >= 2)
```

### 단순 재귀: 중복 계산 발생

```python
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
```

`fib(5)`를 구할 때 `fib(3)` 등을 여러 번 계산하게 된다. 호출 수가 지수적으로 커져서 큰 입력에서는 비효율적이다.

## 4. Top-down: 재귀 + 메모이제이션

**Top-down**은 재귀로 문제를 풀되, 계산한 답을 저장하는 방법이다. 이를 **메모이제이션(memoization)**이라고 한다.

### 방법 A: 딕셔너리로 직접 저장

```python
def fib(n):
    memo = {0: 0, 1: 1}

    def dfs(x):
        if x in memo:       # 이미 구한 상태면 재사용
            return memo[x]

        memo[x] = dfs(x - 1) + dfs(x - 2)
        return memo[x]

    return dfs(n)

print(fib(6))  # 8
```

- `memo[x]`는 **입력 `x`에 대한 정답**이다.
- `memo[x] = ...`처럼 딕셔너리의 원소를 수정할 때는 `nonlocal`이 필요 없다.

### 방법 B: `@cache` 사용 (Python 3.9 이상)

```python
from functools import cache

@cache
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(6))  # 8
```

`@cache`가 인자별 반환값을 자동 저장한다. Python 버전 호환성이 필요하면 `@lru_cache(maxsize=None)`을 사용할 수 있다.

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
```

**주의:** Top-down은 재귀를 사용하므로 Python의 재귀 깊이 제한에 걸릴 수 있다. 상태 수가 크고 단순한 순서로 계산할 수 있다면 Bottom-up이 편리하다.

## 5. Bottom-up: 반복문 + DP 테이블

**Bottom-up**은 초기값을 먼저 적고 작은 상태부터 차례대로 계산하는 방법이다.

```python
def fib(n):
    if n <= 1:
        return n

    dp = [0] * (n + 1)  # dp[0] ~ dp[n]
    dp[0] = 0
    dp[1] = 1

    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]

    return dp[n]

print(fib(6))  # 8
```

| i | dp[i] | 계산 |
|---|---:|---|
| 0 | 0 | 초기값 |
| 1 | 1 | 초기값 |
| 2 | 1 | `dp[1] + dp[0]` |
| 3 | 2 | `dp[2] + dp[1]` |
| 4 | 3 | `dp[3] + dp[2]` |
| 5 | 5 | `dp[4] + dp[3]` |

각 `dp[i]`를 **한 번씩만 계산**하므로 효율적이다.

### Top-down vs Bottom-up

| 구분 | Top-down | Bottom-up |
|---|---|---|
| 기본 형태 | 재귀 + 캐시 | 반복문 + 테이블 |
| 계산 순서 | 필요한 상태부터 | 작은 상태부터 |
| 장점 | 재귀 점화식을 그대로 작성하기 쉬움 | 호출 스택 문제를 피하기 쉬움 |
| 주의점 | 재귀 깊이, 캐시 관리 | 테이블 크기, 초기값, 순서 |
| 피보나치 시간 | O(N) | O(N) |

## 6. 공간 최적화: 이전 값만 저장

`dp[i]`를 구할 때 `dp[i-1]`, `dp[i-2]`만 필요하다면 **전체 배열 없이 두 변수**로 계산할 수 있다.

```python
def fib(n):
    if n <= 1:
        return n

    prev2, prev1 = 0, 1
    for _ in range(2, n + 1):
        curr = prev2 + prev1
        prev2, prev1 = prev1, curr

    return prev1
```

- 시간복잡도: **O(N)**
- 추가 공간복잡도: **O(1)**

**단,** 이전의 여러 상태를 다시 조회해야 하는 문제라면 배열이나 딕셔너리로 저장하는 편이 낫다.

## 7. 실전 연결: 프로그래머스 멀리 뛰기

문제: [프로그래머스 Lv.2 - 멀리 뛰기](https://school.programmers.co.kr/learn/courses/30/lessons/12914)

한 번에 1칸 또는 2칸을 뛸 수 있을 때, 정확히 `n`칸에 도착하는 방법의 수를 구한다.

### ① 상태 정의

`dp[i]` = **정확히 `i`칸에 도착하는 서로 다른 방법의 수**

### ② 마지막 이동을 기준으로 나누기

- 마지막에 **1칸** 뛰었다면, 그 직전에는 `i-1`칸에 있었다.
- 마지막에 **2칸** 뛰었다면, 그 직전에는 `i-2`칸에 있었다.
- 두 경우는 겹치지 않으므로 **더한다**.

```text
dp[i] = dp[i-1] + dp[i-2]
```

### ③ 초기값 확인

| n | 방법 | dp[n] |
|---|---|---:|
| 1 | (1) | 1 |
| 2 | (1,1), (2) | 2 |
| 3 | (1,1,1), (1,2), (2,1) | 3 |
| 4 | (1,1,1,1), (1,1,2), (1,2,1), (2,1,1), (2,2) | 5 |

따라서 `dp[1] = 1`, `dp[2] = 2`로 시작할 수 있다.

### ④ 직접 구현해보기 (빈칸 연습)

아래는 **완성 코드가 아닌 연습용 틀**이다.

```python
def solution(n):
    MOD = 1234567
    if n == 1:
        return 1

    dp = [0] * (n + 1)
    dp[1], dp[2] = 1, 2

    for i in range(3, n + 1):
        # TODO: 이전 두 상태로 dp[i] 계산
        # TODO: 문제에서 요구한 MOD 적용
        pass

    return dp[n]
```

**왜 나머지 연산을 할까?** 경우의 수가 커질 수 있기 때문이다. 덧셈에서는 다음 성질을 이용할 수 있다.

```python
(a + b) % MOD == ((a % MOD) + (b % MOD)) % MOD
```

이 문제와 피보나치는 점화식 형태가 비슷하지만 **초기값과 상태의 의미가 다르다**.

## 8. Python에서 자주 쓰는 문법

DP 전용 내장 함수는 없다. 아래는 DP를 구현할 때 자주 쓰는 **일반 Python 도구**다.

| 문법 | 용도 | 예시 |
|---|---|---|
| 리스트 생성 | 1차원 DP 테이블 | `dp = [0] * (n + 1)` |
| 2차원 리스트 | 격자·두 상태 인덱스 | `dp = [[0] * m for _ in range(n)]` |
| 인덱스 접근 | 계산 결과 조회·갱신 | `dp[i] = dp[i-1] + 1` |
| `dict` | 필요한 상태만 저장 | `memo[(i, j)] = value` |
| `@cache` | 재귀 반환값 자동 저장 | `from functools import cache` |
| `min()` / `max()` | 최적값 점화식 | `dp[i] = min(a, b)` |
| `float('inf')` | 최솟값 문제의 초기값 | `dp = [float('inf')] * (n+1)` |
| `%` | 경우의 수 나머지 처리 | `dp[i] %= 1234567` |

### 2차원 리스트 초기화 주의

```python
# 올바른 방법: 각 행이 독립적인 리스트
DP = [[0] * 3 for _ in range(2)]
DP[0][0] = 7
print(DP)  # [[7, 0, 0], [0, 0, 0]]

# 피해야 할 방법: 모든 행이 같은 리스트를 참조
wrong = [[0] * 3] * 2
wrong[0][0] = 7
print(wrong)  # [[7, 0, 0], [7, 0, 0]]
```

## 9. 시간복잡도와 공간복잡도

DP의 계산량을 판단할 때는 보통 다음처럼 생각한다.

> **시간복잡도 ≈ 상태의 개수 × 상태 하나를 계산하는 비용**

| 예시 | 상태 수 | 상태별 계산 | 시간복잡도 | 추가 공간복잡도 |
|---|---:|---:|---:|---:|
| 피보나치 단순 재귀 | 반복 계산 다수 | 분기 2회 | O(2^N) 상한 | O(N) 호출 스택 |
| 피보나치 Top-down | N개 | O(1) | O(N) | O(N) 캐시 + 스택 |
| 피보나치 Bottom-up | N개 | O(1) | O(N) | O(N) 테이블 |
| 피보나치 두 변수 | N개 | O(1) | O(N) | O(1) |
| N × M 격자 DP | N×M개 | O(1) 가정 | O(NM) | O(NM) 테이블 |

점화식에서 각 상태를 계산할 때 다른 상태를 K개 확인한다면 O(상태 수 × K)가 될 수 있다.

**참고:** 단순 피보나치 재귀의 실제 증가율은 약 `φ^N`이며, O(2^N)은 알기 쉬운 상한 표기다.
